# Спека: полное код-ревью контент-завода (14.08.2026)

## Problem Statement

Контент-завод после двух ранов (Ран 1 — фиксы по ревью 13.08, Ран 2 — UX-2 меню/быстрые сценарии, задеплоен 14.08) заявлен как почти готовый, но вердикт по нему после деплоя UX-2 никто не выносил. Пользователю нужен **полный повторный аудит текущей версии** (все 24 воркфлоу построчно, как 13.08) с вердиктом «готов / не готов». Главное условие: **ни одного кредита scrapecreators/creatify** (даже GET) до полной готовности — ревью должно быть 0-кредитным. Пользователь высказал два подозрения, которые должны быть проверены как блокеры: (1) в боте нет сценария текстовых постов (только видео), (2) автоматический режим не настроен (только ручной).

## Solution

Провести полное статическое ревью всех 24 воркфлоу n8n построчно + сверку DEPLOYMENT.md с фактом на сервере (read-only SSH, 0 кредитов) + контроль всех хвостов ревью 13.08 + проверку двух блокеров пользователя. Выдать `docs/CODE-REVIEW-2026-08-14.md` с вердиктом и доказательствами. Фиксы НЕ применять — отдельный цикл волнами после «ок» пользователя.

## Решения интервью (14.08, дословно)

1. **Объём**: полный повтор — все 24 воркфлоу построчно заново (как 13.08) + сверка деплоя + хвосты 13.08. Статус-чек остальных компонентов.
2. **Критерии вердикта**: как в прошлый раз (п.1 функциональность: все тикеты DONE + базовый контур `start_cycle→аналитика→сценарий→генерация→publish` работает без блокеров; п.2 кредиты: нет BLOCKED из-за нулевых балансов; зависимости заказчика — postmypost-аккаунты, модерация аватаров — вне критерия) **плюс два новых блокера**:
   - **п.3**: сценарий текстовых постов (Threads и подобные, без видео) должен существовать в боте. Если ревью подтвердит отсутствие → вердикт НЕ ГОТОВ + фикс-тикет в волну.
   - **п.4**: режим `auto` должен быть настроен (не только `manual`). Если подтвердится, что auto не настроен → вердикт НЕ ГОТОВ + фикс-тикет в волну.
3. **Запрет трат**: «нельзя тратить токены SC и creatify» — ни одного HTTP к платным API, даже GET (у SC profile-эндпоинтов нет кэша, каждый вызов = кредит). LLM-токены и субагенты — не ограничены.
4. **Деливерабл**: отчёт + вердикт. Фиксы — отдельным циклом, волнами, после «ок» (подготовка субагентами → показ → деплой после согласования).
5. **Сверка с сервером**: субагенты ревьюят ТОЛЬКО файлы репо (0 сети, 0 кредитов); оркестратор лично — read-only SSH (docker ps, sqlite readOnly, systemctl, бесплатные GET балансов).
6. **Коммит**: ревью рабочей копии как есть (незакоммиченное); коммит — после вердикта и «ок» по отчёту.

## Метод (0-кредитный)

1. **Субагенты** (по одному тикету = один субагент, свежий контекст, только файлы репо): каждый ревьюит свой кластер по 12-пунктовому чек-листу `references/workflow-review-checklist.md` + пункты блокеров. Сети нет, ключей нет.
2. **Оркестратор**: read-only SSH на сервер 83.166.233.95 (`docker ps`, `sqlite3` readOnly по workflow_entity/webhook_entity/execution_entity/factory.db, `systemctl is-active`, бесплатные GET балансов creatify `/api/remaining_credits/` и SC `/v1/account/credit-balance`), сверка DEPLOYMENT, верификация 🔴-находок по первоисточникам.
3. **Инструменты**: `scripts/validate-workflow-json.py` (BFS, jsCode, callback_data), `scripts/lint-workflow-json.py` (esc, туннели, мёртвые ноды, заглушки), `scripts/check-workflow-paths.py`, `scripts/extract-tg-ux-map.py`, grep-паттерны секретов (строгие, с длинами).
4. Никаких live-тестов, требующих кредитов. Платные ветки проверяются статически (validate/mock/гейты) и «до точки списания» НЕ вызываются.
