## Текстовые посты: НЕТ (в real-режиме), с оговоркой для mock — доказательство из jsCode

**Вердикт: wf-publish (репо-экспорт, 26 нод) НЕ может опубликовать текст-only пост в real-режиме.** Блокер «текстовые посты в боте» на уровне маршрутизации wf-publish НЕ снят.

**Что умеет `Code build details` (доказательство, что details[] текст-only собрать МОЖНО):**
- `contentBase` берётся из `wh.content` → `wh.captions` (string) → `wh.captions.instagram` (строки 68–71);
- `fileIds` = `wh.file_ids` или `$json.file_id` из upload-ветки (74–75);
- `d.content = content` ставится БЕЗУСЛОВНО при непустом content (строка 114);
- ключ `d.file_ids` добавляется ТОЛЬКО в ветках instagram/youtube/tiktok/pinterest/rutube/ok/facebook и ТОЛЬКО при `fileIds.length > 0` (строки 115–142);
- платформы threads/x/vk/telegram/discord/bluesky/mastodon получают деталь `{account_id?, publication_type, content}` — т.е. **чистый текстовый detail**;
- publication_type при пустых file_ids = 1 (POST), `post_at` = `wh.post_at || new Date().toISOString()` (155).

**Где это ломается (маршрутизация, доказательство):**
1. `Switch upload needed` (единственное ветвление по file_ids): правило истинно ТОЛЬКО при `Array.isArray(file_ids) && file_ids.length > 0` → **out0 (skip upload) = file_ids НЕПУСТЫ; fallback out1 = file_ids ПУСТ → `Switch mock upload` → upload-ветка** (connections: `Switch upload needed out[1] -> Switch mock upload`; в real-режиме `Switch mock upload out[1] -> HTTP real upload`). Для text-only (file_ids=[]) поток ВСЕГДА идёт в upload.
2. `HTTP real upload` (real-режим): POST `https://api.postmypost.io/v4.1/upload/init` c `jsonBody: "={{ {project_id: $env.POSTMYPOST_PROJECT_ID, url: $env.WEBHOOK_URL + 'media/' + $('Webhook').first().json.body.generation_id + '.mp4'} }}"`. Проверенный факт: **upload/init РЕАЛЬНО скачивает файл по url**, недоступная ссылка → `422 «Не удалось загрузить файл по ссылке»`. Для текстового поста:
   - без generation_id → url `…/media/undefined.mp4` → 422;
   - с generation_id, но без сгенерированного видео (текст-only) → файла нет → 422;
   - `options: {}` — нет neverError → 422 роняет execution **ДО `Code build details`** → Respond to Webhook не выполняется → вебхук отвечает ошибкой, пост НЕ создан.
3. В mock-режиме «работает», но это НЕ текст: `Code mock upload` возвращает `{id: 12345, file_id: 67890, status: 'FILE_UPLOADED_SUCCESSFULLY', mock: true}` → `Code build details` подхватывает `$json.file_id` → `fileIds=[67890]` → details получают `file_ids: [67890]` → публикуется медиа-пост с фейковым файлом.
4. Косвенное подтверждение со стороны вызывающего: `wf-tg-bot → CP Build publish body` для текстового сценария шлёт `file_ids: []` + `captions: {}` + `content: full_text` — ровно тот кейс, который падает на п.2 (jsCode: `const fileIds = (typeof c.video_output_url === 'string' && c.video_output_url.length > 0) ? [c.video_output_url] : [];`).

**Фикс (рекомендация):** в `Switch upload needed` добавить отдельную ветку «text-only» — при `file_ids` пуст И `generation_id` отсутствует/платформы не видео → `NoOp skip upload` (третье правило или гейт по platforms), upload-ветку разрешать только при реальном медиа (generation_id + видео-платформы). Проверить живьём: text-only payload `{platforms:['threads','x','vk'], content:'…'}` → ожидается publication без file_ids, а не 422 на upload/init.
