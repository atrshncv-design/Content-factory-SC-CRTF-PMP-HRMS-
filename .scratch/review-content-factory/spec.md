## 1. Критерий вердикта готовности

Вердикт выносится по 2 условиям (зафиксировано в Q4):
1. **Функциональность**: все 21 тикет TICKETS-EXPANSION.md = DONE, базовый контур
   (onboard → analytics → script → generate → publish) работает без ошибок.
2. **Кредиты**: нет тикетов BLOCKED по причине нулевого баланса (SC и creatify пополнены).

Вердикты: ГОТОВ / НЕ ГОТОВ / ГОТОВ С ОГРАНИЧЕНИЯМИ + обоснование.

## 2. Чек-лист анализа воркфлоу (на каждый JSON)

Для каждого из 24 воркфлоу (`workflows/*.json`) проверить:
- [ ] Контракт входа/выхода webhook против `specs/API-REFERENCES.md` и тикета.
- [ ] Mock/real-переключатели (Switch `$env.<KEY> === 'PLACEHOLDER_UNTIL_TOMORROW'` → mock/real).
- [ ] Ветки валидации ошибок: невалидный вход → осмысленная ошибка, НЕ уход в платный HTTP.
- [ ] low_credits-гейты (пороги: creatify floor 50/30/20/10, SC — баланс до вызова).
- [ ] Авторизация: httpHeaderAuth/keypair, `$env`-заголовки, тип ноды ≥4.5, contentType json.
- [ ] `jsonBody` без вложенных `{{ }}` (паттерн Code-нода Build body → `={{ $json.payload }}`).
- [ ] Идемпотентность (creatify-webhook по creatify_id, INSERT OR IGNORE в competitors).
- [ ] webhookId/имена нод без пробелов (питфолл tg-trigger).
- [ ] Секреты: нет inline-ключей в JSON, нет замаскированных значений.
- [ ] SSRF-защита (onboard: запрет 10/8, 172.16/12, 192.168/16, 127/8).
- [ ] Error-handling: retry/backoff на HTTP-нодах, fallbackOutput на Switch, neverError где нужно.
- [ ] Escaping Telegram (esc() в Format-нодах, `_` не в статичных текстах).
