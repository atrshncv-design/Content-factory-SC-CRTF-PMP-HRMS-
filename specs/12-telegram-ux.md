# Спека 12 — Telegram UX: команды, состояния, кнопки, ограничения

**Фаза:** P0 (доработка перед Фазой 2) · **Статус:** к реализации
**Суперседит:** раздел 4-5 спеки 06 и раздел «Ручной режим» orchestrator/SKILL.md

> Проблема, которую решает: без формального UX Hermes «гуляет» — отвечает на
> любые вопросы, выдумывает данные, не держит контекст диалога. Эта спека
> фиксирует **конечный автомат** состояний, точные шаблоны сообщений и
> **жёсткие ограничения** (что бот НЕ делает никогда).

## 1. Принцип

Hermes-бот контент-завода — **не chat-bot общего назначения**. Это интерфейс
оператора к циклу генерации. Любой ввод делится на 3 категории:

1. **Slash-команда** (`/start`, `/help`, `/status`, …) → детерминированный ответ.
2. **Inline-кнопка** (callback от этапа цикла) → переход состояния.
3. **Свободный текст** → интерпретируется **только в рамках активного состояния**
   (например, при `CYCLE_SCRIPT_EDIT` ждём новый текст сценария). Вне состояния
   `IDLE` или активного шага → отказ с подсказкой `/help`.

**Запрещено:** отвечать на вопросы не о контент-заводе («какая погода»,
«напиши стих», «что ты умеешь» — за пределами справки).

## 2. Карта состояний (state machine)

```
                       ┌──────────┐
                       │  IDLE    │ ◄────────────────────────────┐
                       └────┬─────┘                              │
                            │                                    │
            ┌───────────────┼───────────────┐                    │
            ▼               ▼               ▼                    │
     /onboard <url>   /start_cycle    /mode auto + cron 09:00    │
            │               │               │                    │
            ▼               ▼               ▼                    │
   ONBOARDING_PENDING  CYCLE_ANALYTICS   AUTO_CYCLE_RUNNING      │
            │               │                                    │
       (профиль            ▼                                    │
        готов)        CYCLE_ANALYTICS_PENDING                   │
            │           (тема, ждём approve/edit/reject/alt)    │
            │               │ approve                            │
            │               ▼                                    │
            │          CYCLE_SCRIPT_PENDING                      │
            │           (сценарий, ждём approve/edit/reject)     │
            │               │ approve                            │
            │               ▼                                    │
            │          CYCLE_GENERATION_PENDING                  │
            │           (видео генерится, ждём creatify-callback)│
            │               │ callback done                      │
            │               ▼                                    │
            │          CYCLE_VIDEO_PENDING                       │
            │           (видео готово, ждём publish/regen/reject)│
            │               │ publish                             │
            │               ▼                                    │
            │          CYCLE_PUBLISH_PENDING                     │
            │           (выбор платформ и времени)               │
            │               │ approve + time                     │
            └───────────────┴────────────────────────────────────┘
                              (→ IDLE или AUTO продолжение)

Любое состояние → /cancel → IDLE (с пометкой артефактов как abandoned).
Любое состояние + сбой → алерт в TG → IDLE.
```

State хранится в `~/.hermes/memories/MEMORY.md` (одна строка:
`STATE: CYCLE_SCRIPT_PENDING | topic_id=17 | started_at=...`).

## 3. Slash-команды — полный реестр

| Команда | Действие | Доступ |
|---------|----------|--------|
| `/start` | Приветствие + главное меню (кнопки: Запустить цикл / Статус / Помощь / Сменить режим). | operator+ |
| `/help` | Список команд с описанием. | operator+ |
| `/status` | Сводка: режим, активный клиент, кредиты creatify, сегодня N видео, последний цикл. | operator+ |
| `/mode manual\|auto` | Переключить режим. Запись в `settings.mode`. | admin |
| `/onboard <url>` | Запустить онбординг клиента по URL. | admin |
| `/start_cycle` | Запустить цикл (→ CYCLE_ANALYTICS). | operator+ |
| `/cancel` | Отменить текущий ждущий шаг, вернуться в IDLE. | operator+ |
| `/topics` | Список тем за сегодня (chosen + rejected). | operator+ |
| `/competitors` | Список конкурентов активного клиента. | operator+ |
| `/accounts` | Статус подключённых соцсетей (из postmypost). | operator+ |
| `/budget` | Подробно по creatify: остаток кредитов, лимиты, прогноз. | operator+ |
| `/client <id>` | Сменить активного клиента (мульти-тенант P2). | admin |
| `/clients` | Список клиентов. | admin |
| `/reload_skills` | Перечитать skills (для разработки). | admin |
| `/ping` | Health-check: "✅ Бот работает. Hermes uptime N min." | operator+ |

**Где `operator+`** = operator и admin. `admin` = только admin (роль в таблице `users`).

## 4. Inline-кнопки по этапам цикла

> Hermes-telegram поддерживает inline-keyboard. Каждая кнопка = callback_data
> с зашитым действием и id сущности.

### Этап 1 — Аналитика (тема)

```
📊 Этап 1/4 — Тема выбрана

🎯 {title}
Источник: {source_url}
Метрики: {views}👁  {likes}❤  {shares}🔁  ({age_hours}ч назад)
Виральность: {virality_index}
Реализуемость через creatify: {feasibility}

Почему выбрал: {rationale}
Адаптация под клиента: {adaptation_for_client}
Длина ролика: {target_length} сек

[ ✅ Утвердить ]   [ ✏️ Изменить ]
[ ❌ Отклонить ]   [ 🔄 Другая тема ]
```

callback_data: `approve:topic:{id}` / `edit:topic:{id}` /
`reject:topic:{id}` / `alt:topic:{id}`

### Этап 2 — Сценарий

```
✍️ Этап 2/4 — Сценарий готов ({target_length} сек, ~{words} слов)

🪝 HOOK (3 сек):
{hook}

📖 BODY (~20 сек):
{body}

🎯 CTA (3-5 сек):
{cta}

──────────────
📝 Полный текст для озвучки:
{full_text}

[ ✅ Утвердить ]   [ ✏️ Изменить ]
[ ❌ Отклонить ]
```

callback_data: `approve:script:{id}` / `edit:script:{id}` / `reject:script:{id}`

При `edit` → переход в `CYCLE_SCRIPT_EDITING`, бот пишет:
> "Пришли новый текст сценария одним сообщением. /cancel — отмена."

### Этап 3 — Видео

```
🎬 Этап 3/4 — Видео готово ({length} сек, потрачено {credits} кредитов)

[превью MP4 как видео-сообщение]

Сценарий: {script_excerpt}
Аватар: {avatar_name}
Голос: {voice_name}

[ ✅ Опубликовать ]   [ ✏️ Перегенерировать ]
[ ❌ Отклонить ]
```

callback_data: `publish:gen:{id}` / `regen:gen:{id}` / `reject:gen:{id}`

### Этап 4 — Площадки и время

```
📤 Этап 4/4 — Куда публикуем?

☑️ Instagram Reels
☑️ YouTube Shorts
☐ TikTok
☐ Telegram
☐ Threads (текст)
☐ X (текст)

⏰ Время:
[ Сейчас ]   [ +2 часа ]   [ Завтра 12:00 ]

[ 📤 Запланировать ]
```

callback_data: `toggle:platform:instagram` / `schedule:now` / `schedule:2h` /
`schedule:tomorrow_12` / `confirm:publish`

## 5. Жёсткие ограничения для Hermes (ядро промпта)

Эти правила **вписываются в начало orchestrator/SKILL.md** жирным шрифтом.
Hermes обязан следовать им без исключений.

```
┌──────────────────────────────────────────────────────────────────┐
│  ТЫ — ТОЛЬКО ОРКЕСТРАТОР КОНТЕНТ-ЗАВОДА.                          │
│                                                                  │
│  ✗ НЕ отвечай на вопросы вне тематики контент-завода             │
│    (погода, стихи, программирование, философия, etc.).           │
│    Стандартный отказ: "Я — бот контент-завода. Работаю только    │
│    с командами из /help. По другим вопросам обратись к человеку."│
│                                                                  │
│  ✗ НЕ выдумывай данные. Если wf-analytics не вернул кандидатов   │
│    — НЕ придумывай темы сам. Сообщи оператору: "Аналитика пуста, │
│    попробуй /start_cycle позже или смени нишу в /settings."      │
│                                                                  │
│  ✗ НЕ отступай от порядка цикла: analytics → topic → script →    │
│    json → generate → publish. Между этапами — обязательно пауза  │
│    на решение оператора (в manual режиме).                       │
│                                                                  │
│  ✗ НЕ запускай цикл, если активный клиент не задан.              │
│    Ответ: "Сначала /onboard <url>."                              │
│                                                                  │
│  ✗ НЕ генерируй видео, если превышен лимит (daily/monthly/credit │
│    floor). Сообщи оператору и останови цикл.                     │
│                                                                  │
│  ✗ НЕ комментируй действия оператора, не задавай уточняющих      │
│    вопросов "а вы уверены?" — только執行命令.                     │
│                                                                  │
│  ✓ Любая непонятная команда → "Не понял. /help — список команд." │
│  ✓ Любой callback с неизвестным action → ignored + лог warn.     │
│  ✓ Сообщения от user_id вне whitelist → ignored.                 │
└──────────────────────────────────────────────────────────────────┘
```

## 7. Что НЕ делает бот (явный список)

| Запрос | Реакция бота |
|--------|--------------|
| «Напиши стих» | ❌ "Я — бот контент-завода. /help" |
| «Какая погода» | ❌ "Я — бот контент-завода. /help" |
| «Расскажи о себе» | ❌ "Я — бот контент-завода. /help" (кроме как в /start) |
| «Сгенерируй сценарий про X» (вне цикла) | ❌ "Сначала /start_cycle. Внутри цикла я предложу тему." |
| «Опубликуй в Instagram вот это» | ❌ "Публикация возможна только внутри цикла после /start_cycle." |
| Любой текст вне активного шага | ❌ "Не понял команду. /help" |
| Сообщение от user_id вне whitelist | игнор (без ответа) |
| Незнакомая slash-команда | ❌ "Не знаю такую команду. /help" |

## 8. Реализация (задачи для разработчика Фазы 2)

1. **Обновить `~/.hermes/skills/content-factory/orchestrator/SKILL.md`** — добавить
   разделы 5, 6, 7 этой спеки дословно.
2. **Slash-команды** — Hermes поддерживает их нативно через telegram gateway.
   Зарегистрировать через `hermes gateway setup` → Telegram →
   "Edit command list" ( BotFather или через gateway config).
3. **State machine** — запись в MEMORY.md после каждого перехода.
   Перед каждым ответом Hermes читает MEMORY.md, знает текущее состояние.
4. **Inline-кнопки** — Hermes-telegram поддерживает reply_markup.
   callback_data кодирует действие и id.
5. **Whitelist** — уже работает (`TELEGRAM_ALLOWED_USERS`).
6. **Тесты**:
   - «Напиши стих» → отказ.
   - `/start` без активного клиента → подсказка про `/onboard`.
   - `/start_cycle` → переход в CYCLE_ANALYTICS_PENDING.
   - В состоянии CYCLE_SCRIPT_PENDING свободный текст «какая погода» → отказ
     (не интерпретируется как сценарий).
   - `/cancel` из любого состояния → IDLE.
