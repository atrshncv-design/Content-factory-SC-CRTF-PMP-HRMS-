# Спека 00 — Архитектура и инфраструктура

**Фаза:** P0 · **Статус:** к реализации

## 1. Принцип

`n8n (руки + будильник) ↔ Hermes (мозг) ↔ SQLite (память) → TG-бот (интерфейс)`

Разделение ответственности:
- **n8n** — исполнение: cron-триггеры, HTTP-вызовы к API, приём вебхуков,
  хранение визуальных воркфлоу, история исполнений, retries.
- **Hermes** — принятие решений: выбор темы, сценарий, сборка JSON. Управляет
  n8n через n8n REST API (запускает воркфлоу, читает результат).
- **SQLite** — память: состояние цикла, артефакты (тема → сценарий → задача),
  настройки, логи.
- **TG-бот** (на н8n-нодах) — человек в цикле.

## 2. Компоненты и развёртывание

Всё на **одном сервере** (self-hosted). Минимальные требования для витринного:
2 vCPU, 4 GB RAM, 40 GB SSD (видео хранятся ≤ 7 дней, потом чистка).

```
┌──────────────────────────── сервер ────────────────────────────┐
│                                                                │
│   ┌──────────┐   webhook    ┌────────────┐    REST API         │
│   │  n8n     │◄─────────────│ external   │──────────────┐      │
│   │ (Docker) │              │ (creatify) │              │      │
│   │          │──HTTP──────► │ scrapecr.  │              │      │
│   │          │──HTTP──────► │ postmypost │              ▼      │
│   │          │              └────────────┘      ┌────────────┐ │
│   │          │◄──── n8n REST API ───────────────│  Hermes    │ │
│   │          │──── wake Hermes (webhook) ──────►│ (deepseek) │ │
│   │          │                                  └────────────┘ │
│   │          │── SQL ──► /var/data/factory.db (SQLite)         │
│   │          │── TG API ──────────────────────► Telegram       │
│   │          │── FS write ────────────────────► /var/media/    │
│   └──────────┘                                                 │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 2.1 Развёртывание через Docker Compose

Один `docker-compose.yml`, три сервиса + тома:

| Сервис | Образ | Порт | Том |
|--------|-------|------|-----|
| `n8n` | `n8nio/n8n:latest` | 5678 | `./n8n-data` (воркфлоу, креды, история) |
| `hermes` | кастомный (см. спеку 03) | 8000 | `./hermes-data` (промпты, конфиги) |
| `sqlite` | — (файл, не контейнер) | — | `./data/factory.db` (shared volume) |

`/var/media/` — каталог для готовых MP4, с cron-чисткой раз в сутки
(файлы старше 7 дней → удаляются).

> Hermes и n8n на одном хосте → нулевая сетевая задержка между ними,
> упрощённая безопасность (взаимодействие через localhost).

## 3. Потоки данных (главные сценарии)

### 3.1 Авто-режим — утренний цикл

```
[cron n8n 09:00] ──wake──► [Hermes: orchestrator]
        │
        ├─ (1) Hermes → n8n: запустить workflow "analytics"
        │     └─ n8n: HTTP scrapecreators (IG/TikTok/YT search 12-72ч)
        │        └─ результат → Hermes
        │     └─ Hermes → субагент-Аналитик: выбрать тему дня
        │
        ├─ (2) Hermes → субагент-Сценарист (контекст: тема) → сценарий ролика
        │
        ├─ (3) Hermes → субагент-JSON-сборщик (контекст: сценарий)
        │     └─ валидный JSON для POST /api/link_to_videos
        │     └─ Hermes → n8n: workflow "creatify-submit" (POST + webhook_url)
        │        └─ creatify шлёт webhook → n8n workflow "creatify-webhook"
        │           └─ n8n: скачать MP4 в /var/media/, записать в БД, → Hermes
        │
        └─ (4) Hermes → n8n: workflow "publish" (upload + post)
              └─ postmypost: запланировать публикацию
```

### 3.2 Ручной режим — верификация на каждом шаге

На каждом из 4 этапов Hermes ставит паузу и шлёт в TG сообщение с inline-кнопками
`✅ Утвердить / ✏️ Изменить / ❌ Отклонить`. n8n-воркфлоу ждёт callback от TG,
после утверждения передаёт управление дальше. Подробно — см. спеку 06.

### 3.3 Вебхук готовности ролика от creatify

```
creatify ──POST──► [n8n workflow "creatify-webhook" :production/webhook/creatify]
   payload: { id, status, video_output, failed_reason }
   ─► n8n: проверить id есть в БД (идемпотентность)
   ─► if status==done: скачать video_output → /var/media/<id>.mp4
   ─► обновить строку в generations (status=done, local_path)
   ─► уведомить Hermes (HTTP на :8000/internal/creatify-done)
   ─► уведомить TG (для ручного режима — кнопка "Опубликовать?")
```

## 4. Безопасность

### 4.1 Секреты
- Все ключи **только в `.env`** на сервере (ответ пользователя: env).
- `.env` имеет права `600`, владелец — сервисный пользователь, не root.
- В git — `.gitignore` с `.env`, `*.db`, `n8n-data/`, `media/`.
- В n8n креды хранятся зашифрованными (использует `N8N_ENCRYPTION_KEY`).
- **Никогда** не светить ключи в логах n8n/Hermes; в спеке 03 описано, как
  Hermes ссылается на ключи по имени, а реальные значения подставляет n8n.

### 4.2 Сетевая безопасность
- n8n webhook-эндпоинт (для приёма creatify) — единственный публично
  доступный маршрут: `https://<домен>/webhook/creatify`.
- Остальное (n8n UI :5678, Hermes :8000) — **только localhost** или за VPN/SSH.
- HTTPS на публичном домене через reverse-proxy (Caddy/nginx) + Let's Encrypt.
- Доп. защита webhook creatify: проверка наличия `id` в БД + секретный путь
  (path-based token), т.к. creatify не шлёт подпись.

### 4.3 Доступ к TG-боту
- Whitelist `TELEGRAM_ALLOWED_USER_IDS` (id пользователя + коллеги).
- Любое сообщение от id вне списка → игнор (можно «доступ запрещён»).
- См. спеку 06.

### 4.4 Защита от перерасхода бюджета creatify
- **Хард-лимит** `CREATIFY_DAILY_VIDEO_LIMIT=3` (видео/день в авто-режиме).
- Перед каждым `POST /api/link_to_videos` — проверка счётчика в БД за сегодня.
- Лимит кредитов: `CREATIFY_CREDIT_FLOOR=50` — если остаток (через
  `GET /api/remainingcredits/`) ниже порога, авто-режим останавливается + алерт в TG.
- Лимит в 100 видео/мес проверяется суммированием generations за месяц.

## 5. Устойчивость и обработка сбоев

| Сбой | Поведение |
|------|-----------|
| scrapecreators 402/500/429 | n8n: retry с экспоненциальной задержкой (3 попытки), затем пропуск этапа + алерт |
| creatify failed/rejected | записать `failed_reason` в БД, алерт в TG, **не** ретраить автоматически (стоит кредитов) — ручной рестарт кнопкой в TG |
| creatify webhook не пришёл | компенсирующий поллинг: каждые 5 мин n8n батчем `GET /api/link_to_videos/?ids=` по задачам старше 15 мин без callback |
| postmypost 429 | очередь с уважением `Retry-After` (лимит 10 постов/мин) |
| postmypost publication_status=3 (ERROR) | алерт в TG, пометить пост как failed, не ретраить авто |
| Deepseek/Hermes недоступен | n8n: retry вызова Hermes, при отказе — алерт + пауза цикла |
| БД locked (SQLite) | WAL-mode (см. спеку 01), retry с коротким backoff |

## 6. Ротация и хранение (лёгкая БД, нагрузка на RAM ≈ 0)

- Логи — удалять записи старше 7 дней (cron-задача в n8n, ежедневно 03:00).
- Готовые MP4 — удалять старше 7 дней из `/var/media/` (cron, ежедневно 03:30).
- Резерв: MP4 дублируются отправкой в TG-канал-архив (как «резервная память»).
- SQLite: еженедельный `VACUUM` для сжатия.

## 7. Что не входит в MVP (явно)

- Дашборд (Next.js) — P2.
- Аналитика собственных роликов (сбор метрик по своим постам) — P2.
- Мульти-тенантность / сеть аккаунтов клиентов — после первого клиента.
- Английский язык — заложить `language` параметр, но UI/промпты пока только RU.
- Кастомные аватары creatify (BYOA) — пока только библиотечные.

## 8. Критерии готовности P0

1. Сервер поднят, n8n + Hermes + SQLite работают по docker-compose.
2. Все 4 ключа (3 API + Deepseek + TG) настроены, `GET /accounts` (postmypost)
   и `GET /api/remainingcredits/` (creatify) отвечают 200.
3. Ручной режим: аналитика → утверждение → сценарий → утверждение →
   генерация 1 видео → утверждение → публикация в 1 соцсеть (Instagram Reels).
4. Логи пишутся, вебхук creatify принимается и обрабатывается.
5. Алерты об ошибках приходят в TG.
