# Спека 03 — Агенты Hermes (3 субагента)

**Фаза:** P0 · **Статус:** к реализации

> Исполнитель: **Hermes** на базе deepseek v4 (большие лимиты токенов).
> Платформа: self-hosted, один сервер с n8n (см. спеку 00).
> Стиль оркестрации: **последовательно + контекст** — каждый следующий субагент
> получает артефакт предыдущего в промпте.

## 1. Роли

Hermes выступает в 5 ролях (1 оркестратор + 4 субагента). Субагенты создаются
с **изолированным контекстом** под конкретную задачу (Hermes это умеет).

| Роль | Когда запускается | Вход | Выход |
|------|-------------------|------|-------|
| **Оркестратор** | триггер цикла (cron/кнопка) | — | управляет очерёдностью, пишет в БД, шлёт TG |
| **Субагент 0: Онбординг** | по требованию (`/onboard <url>`) | URL клиента | профиль клиента (`clients` + `client_socials` + seed-конкуренты) |
| **Субагент 1: Аналитик** | в цикле, после аналитики | топ-20 кандидатов от n8n | выбранная тема дня (`topics` row) |
| **Субагент 2: Сценарист** | в цикле, после Аналитика | выбранная тема | сценарий ролика (`scripts` row) |
| **Субагент 3: JSON-сборщик** | в цикле, после Сценариста | сценарий | валидный JSON для `POST /api/link_to_videos` |

> Субагент 0 (Онбординг) выделен отдельно — он не часть ежедневного цикла, а
> сервис «по кнопке». Подробно — спека 08. Оркестратор держит контекст активного
> клиента (`settings.active_client_id`) и подставляет его во все остальные субагенты.

## 2. Оркестратор

Не субагент — это сам Hermes в «главном» контексте. Отвечает за:

1. **Старт цикла:** принимает wake-вызов от n8n (cron 09:00 или кнопка «Старт» в TG).
2. **Очерёдность:** запускает n8n-воркфлоу `wf-analytics` → получает топ-20 →
   передаёт Аналитику → … → JSON-сборщику → запускает `wf-creatify-submit`.
3. **Паузы в ручном режиме:** после каждой роли шлёт в TG результат и ждёт
   callback (`✅ Утвердить / ✏️ Изменить / ❌ Отклонить`). В авто-режиме — пауз нет,
   сразу следующий шаг.
4. **Бюджетные проверки:** перед вызовом JSON-сборщика → проверка дневного и
   месячного лимита видео (из БД), при превышении — стоп + алерт.
5. **Запись в БД:** артефакты каждого этапа пишутся в `topics`/`scripts`/
   `generations`.
6. **Обработка сбоев:** при ошибке любой роли → алерт в TG с причиной,
   состояние цикла → `failed`, ручной рестарт по кнопке.

### Контекст оркестратора (system prompt — скелет)

```
Ты — оркестратор контент-завода. Ниша клиента: {client_niche}.
Тон: {client_tone}. Сегодняшняя дата: {today}.

Твоя задача — провести цикл генерации через 3 субагента последовательно:
Аналитик → Сценарист → JSON-сборщик. После каждого этапа:
- ручной режим: показать результат оператору в TG, дождаться решения;
- авто-режим: продолжить автоматически.

Правила:
- БЮДЖЕТ: не более {daily_video_limit} видео/день и {monthly_video_limit}/мес.
  Перед генерацией проверяй счётчики в БД.
- При ошибке любого сервиса — не пытаешься «выкрутиться», а сообщаешь оператору.
- Не выдумывай URL/метрики — берёшь только из данных, что дал n8n.
```

## 3. Субагент 1: Аналитик

**Цель:** из топ-20 кандидатов выбрать **одну** тему дня — трендовую,
релевантную нише клиента, **реализуемую** через creatify.

### Вход в промпт
- топ-20 кандидатов (из спеки 02): title, метрики, age_hours, virality, transcript,
  feasibility_hint.
- профиль клиента (ниша, тон, аудитория).
- справка по возможностям creatify (урезанная — см. ниже).

### Справка creatify в промпте (чтобы Аналитик знал, что реально)
```
Creatify URL-to-video делает: видео 15/30/45/60 сек, формат 9:16 (вертикаль),
аватар-спикер + закадровый голос на русском, по URL источника или тексту.
НЕ умеет: сложный монтаж исходников, много дублей, точное клонирование
реального лица (только библиотечные аватары в MVP).
→ ВЫВОД: для creatify подходит контент, который можно пересказать одним
  голосом за 30 сек (демо-факты, мифы, объяснения). НЕ подходит контент,
  завязанный на сложную оригинальную хореографию/музыку/монтаж.
```

### Решение Аналитика
Выбирает тему и формирует структурированный ответ:
```json
{
  "chosen": {
    "title": "Как сварочный робот экономит заводу 40% брака",
    "source_url": "https://instagram.com/reel/...",
    "source_platform": "instagram",
    "rationale": "Высокая виральность (0.91), возраст 28ч, тема точно в нише
       промышленной робототехники, легко пересказать голосом за 30 сек.",
    "feasibility": "high",
    "adaptation_for_client": "Связать с окупаемостью KUKA-роботов за 1-2 года,
       добавить CTA 'бесплатный аудит производства'.",
    "target_length_sec": 30
  },
  "alternatives": [ { "title": "...", "rationale": "запасной вариант" } ]
}
```

> Оркестратор пишет это в `topics` (status=pending, chosen=1). В ручном режиме —
> рендерит в TG с кнопками.

## 4. Субагент 2: Сценарист

**Цель:** по выбранной теме написать **сценарий ролика** под creatify
(закадровый текст + структура).

### Вход в промпт
- выбранная тема (title, rationale, adaptation_for_client, target_length_sec).
- тон клиента, аудитория, ниша.
- структура сценария (см. ниже) — жёсткий шаблон.

### Структура сценария (обязательная)

| Часть | Доля | Назначение |
|-------|------|------------|
| **Hook** | первые 3 сек | цепляет: вопрос/шок-факт/противоречие |
| **Body** | ~20 сек | суть, 2-3 ключевых пункта, цифры/кейс |
| **CTA** | последние 3-5 сек | призыв: «бесплатный аудит» / «заказать консультацию» |

### Выход
```json
{
  "hook": "Знаете, что общий брак на заводе можно снизить на 40% за месяц?",
  "body": "Сварочный робот KUKA работает 24/7 с точностью 0.05 мм. На заводе
    'Автокомпласт' он заменил 3 ручных поста и окупился за 14 месяцев.",
  "cta": "Закажите бесплатный аудит производства — ссылка в описании.",
  "full_text": "<hook> <body> <cta>",
  "target_length_sec": 30,
  "estimated_words": 65,
  "notes": "Озвучка должна быть уверенная, экспертная, без воды."
}
```

> Контроль длины: для 30 сек ≈ 60-70 слов на русском (≈2 слова/сек). Сценарист
> сам считает и держится в лимите. Оркестратор пишет в `scripts` (status=pending).

## 5. Субагент 3: JSON-сборщик

**Цель:** превратить сценарий в **валидный JSON** для `POST /api/link_to_videos`
(спека 04). Это критический шаг — от корректности JSON зависит, пройдёт ли
генерация.

### Вход в промпт
- сценарий (full_text, target_length_sec).
- **полная схема полей `link_to_videos`** (см. спеку 04, раздел «схема»).
- выбор аватара/голоса (из кеша `GET /api/voices/` и `GET /api/personas/` —
  один раз подтянуты, список релевантных для ниши «инженерный эксперт» в БД).
- `webhook_url` (для приёма готовности).
- `language: ru`, `aspect_ratio: 9x16`.

### Жёсткие требования к выводу
1. **Только валидный JSON**, без markdown-обёртки, без пояснений.
2. Все поля — из схемы; enum'ы — строго из допустимых значений.
3. Обязательные поля заполнены; нельзя передавать `null` там, где ждут строку.
4. `video_length` ∈ {15, 30, 45, 60} — из сценария.
5. `webhook_url` подставляется из настроек (не выдумывается).

### Пример ожидаемого выхода
```json
{
  "name": "robotec-welding-20260810",
  "link": "<UUID — будет создан шагом ранее через POST /api/links/>",
  "visual_style": "DynamicProductTemplate",
  "script_style": "ProblemSolutionV2",
  "aspect_ratio": "9x16",
  "video_length": 30,
  "language": "ru",
  "target_audience": "директора заводов, главные инженеры",
  "target_platform": "Instagram",
  "model_version": "aurora_v1_fast",
  "override_script": "<full_text сценария>",
  "override_voice": "<voice_id русского мужского экспертного>",
  "no_background_music": false,
  "background_music_volume": 0.15,
  "voiceover_volume": 1.0,
  "no_cta": false,
  "webhook_url": "https://<домен>/webhook/creatify"
}
```

> Оркестратор **валидирует** JSON (парсинг + проверка обязательных полей и
> enum'ов по чеклисту). Если невалиден — возвращает Сборщику с замечанием
> (один ретрай), затем отдаёт оператору в TG с кнопкой «✏️ Исправить вручную».

### Важная хитрость: link создаётся ДО сборки JSON

Поле `link` — UUID, который возвращает `POST /api/links/`. Поэтому:
1. Оркестратор сначала создаёт link (через n8n `wf-creatify-link`):
   `POST /api/links/` с URL источника (source_url темы) ИЛИ с переопределёнными
   `title`/`description`/`image_urls` (если source — не товарная карточка).
2. Полученный UUID подставляется в промпт Сборщику как уже известное значение.
3. Сборщик отдаёт финальный JSON → Оркестратор → n8n `wf-creatify-submit`.

## 6. Изоляция контекста и расход токенов

- Каждый субагент — отдельный вызов с **своим system prompt** и **только нужным
  вводом** (никаких «вот вся история, разберись»).
- Контекст передаётся **только вперёд**: тема → сценаристу, сценарий → сборщику.
- Оркестратор держит у себя краткое состояние (id выбранных строк), а не весь
  сырой массив аналитики.
- Оценка: ~200k токенов/цикл — укладывается в лимиты deepseek v4.

## 7. Связь с n8n (напоминание из спеки 00)

- Hermes ↔ n8n: Hermes вызывает n8n REST API (`POST /api/v1/workflows/{id}/execute`)
  с входным JSON, получает результат.
- n8n → Hermes: n8n делает HTTP на `http://localhost:8000/internal/<event>`
  (аналитика готова, creatify готов, пост опубликован).
- Все «дорогие» операции (HTTP к API, скачивание файлов) — в n8n. Hermes только
  решает и пишет в БД.

### 7.1 Эндпоинты Hermes (полный список)

| Эндпоинт | Кто вызывает | Назначение |
|----------|--------------|------------|
| `POST /internal/start-cycle` | n8n (cron/кнопка TG/дашборд) | запуск цикла генерации |
| `POST /internal/onboard` | n8n (`/onboard` команда) | старт онбординга (спека 08) |
| `POST /internal/analytics-ready` | n8n (`wf-analytics`) | приём топ-20 кандидатов |
| `POST /internal/decision` | n8n (`wf-tg-incoming`, inline-кнопки) | решение оператора approve/edit/reject |
| `POST /internal/creatify-done` | n8n (`wf-creatify-webhook`) | ролик готов |
| `POST /internal/creatify-failed` | n8n | ролик упал |
| `POST /internal/publish-queued` | n8n (`wf-publish`) | публикация ушла в очередь |
| `POST /internal/performance-digest` | n8n (`wf-self-analytics`, P2) | дайджест метрик для Аналитика |
| `POST /tg/handle` | n8n (`wf-tg-incoming`) | **вся логика TG-бота** (спека 06) — возвращает метод и параметры ответа |
| `GET  /internal/status` | n8n (`/status` команда), дашборд | сводка (режим, кредиты, счётчики) |

> `/tg/handle` — единственная точка логики бота. n8n только пересылает
> {from, text, callback_data} и исполняет возвращённый {method, params}.

## 8. Критерии готовности

1. Цикл из 3 субагентов проходит последовательно, контекст передаётся.
2. Каждый субагент выдаёт ответ в заданном JSON-формате (парсится без ошибок).
3. JSON-сборщик отдаёт JSON, проходящий валидацию по схеме `link_to_videos`.
4. В ручном режиме оператор получает 3 сообщения на верификацию (аналитика,
   сценарий, финальный JSON/превью) и может утвердить/отклонить каждый.
5. При ошибке любой роли — алерт в TG с читаемой причиной.
