# Спека 06 — TG-бот и режимы работы

**Фаза:** P0 · **Статус:** к реализации

> Стек: **n8n = транспорт, Hermes = логика.** n8n держит только Telegram
> Trigger (приём сообщений/callbacks) и Telegram-ноду (отправка). Вся логика
> бота — что ответить, какие кнопки показать, состояние диалога — живёт в
> **Hermes** (тестируется, версонируется, не размазана по визуальным нодам n8n).
>
> **Паттерн каждой ноды n8n:** `Telegram Trigger → HTTP POST в Hermes → Hermes
> возвращает {text, buttons, video_path?} → n8n отправляет через Telegram-ноду`.
> n8n не принимает решений — он передаёт.
>
> Один TG-клиент на всю систему → ноль конфликтов webhook/polling и рассинхрона.
> Режим приёма — webhook на том же домене, что и creatify-webhook.

## 1. Роль бота

Бот = **единственный человеко-читаемый интерфейс** контент-завода (до дашборда в P2).
Через него:
- оператор видит результат каждого этапа и утверждает/отклоняет/правит;
- приходят алерты об ошибках и системных событиях;
- хранятся копии сгенерированных видео (резервная память — отдельный приватный канал-архив).

## 2. Пользователи и доступ

- Whitelist `TELEGRAM_ALLOWED_USER_IDS` (env, список через запятую).
- При первом сообщении от id вне списка → ответ «Доступ запрещён» + лог `warn`.
- Роли (в таблице `users`): `admin` (всё + настройки), `operator` (только цикл).
- В MVP — только `admin` (сам владелец + коллеги).

## 3. Два режима работы

Переключается командой `/mode manual|auto` (значение в `settings.mode`).

### 3.1 Ручной режим (`manual`) — по умолчанию в MVP
Полный цикл идёт с паузами на каждом этапе. Оператор верифицирует:
1. **Аналитика:** бот присылает выбранную тему + обоснование → кнопки
   `✅ Утвердить / ✏️ Изменить / ❌ Отклонить / 🔄 Другая тема`.
2. **Сценарий:** бот присылает текст сценария → `✅ Утвердить / ✏️ Изменить / ❌ Отклонить`.
3. **Готовое видео:** бот присылает MP4 (как видео-сообщение) →
   `✅ Опубликовать / ✏️ Перегенерировать / ❌ Отклонить`.
4. **Площадки:** бот присылает список соцсетей с чекбоксами → оператор выбирает,
   куда постить → `📤 Запланировать` + выбор времени.

### 3.2 Авто-режим (`auto`)
Тот же цикл, но **без пауз**. Cron n8n в 09:00 будит Hermes, тот прогоняет все
3 субагента подряд и отправляет публикацию. Бот используется только для:
- утреннего уведомления «Цикл стартовал»;
- уведомлений о завершении каждого этапа (информационно, без кнопок);
- алертов при сбоях.

## 4. Команды

| Команда | Назначение |
|---------|------------|
| `/start` | приветствие + список команд + текущий режим |
| `/mode manual\|auto` | переключить режим |
| `/start_cycle` | запустить цикл сейчас (ручной запуск в любом режиме) |
| `/status` | текущее состояние: режим, остаток кредитов creatify, видео за месяц, последние посты |
| `/budget` | подробная сводка по бюджету (кредиты, дневной/месячный лимит) |
| `/topics` | список тем за сегодня (включая отклонённые) |
| `/competitors` | список отслеживаемых конкурентов |
| `/accounts` | статус подключённых соцсетей (из postmypost) |
| `/settings` | (admin) просмотр/правка настроек клиента (ниша, тон, лимиты) |
| `/cancel` | отменить текущий ждущий этап (в ручном режиме) |
| `/help` | краткая справка |

## 5. Inline-кнопки (верификация)

Каждая «пауза» в ручном режиме — это сообщение от бота с inline-кнопками.
Callback-данные кодируют действие + id сущности:

```
callback_data = "approve:topic:42"
callback_data = "edit:script:17"
callback_data = "reject:topic:42"
callback_data = "publish:gen:9"
callback_data = "platform:instagram:toggle"   ← для выбора соцсетей
callback_data = "schedule:now | schedule:2h | schedule:tomorrow_12"
callback_data = "retry:gen:9"                  ← ручной рестарт генерации
```

n8n-воркфлоу `wf-tg-callback` ловит `callback_query`, парсит действие, шлёт
соответствующий HTTP в Hermes (`/internal/decision`) или меняет БД напрямую,
затем редактирует сообщение (убрать кнопки, поставить статус ✅/❌).

## 7. Алерты

| Событие | Текст |
|---------|-------|
| creatify `failed` | `⚠️ Генерация #9 failed: <reason>. [🔄 Рестарт]` |
| postmypost `error` | `⚠️ Публикация #12 ошибка: <result>. [🔄 Ретраю]` |
| кредиты < floor | `🚫 Creatify: осталось 45 кредитов (< 50). Авто-режим остановлен.` |
| дневной лимит | `⏸ Достигнут дневной лимит видео (3). Завтра продолжим.` |
| аккаунт требует OAuth | `🔐 Instagram требует перелогина в кабинете postmypost.` |
| scrapecreators 4xx | `⚠️ Аналитика: частичный сбой (TikTok недоступен). Продолжаю с IG+YT.` |
| цикл завершён | `✅ Цикл завершён: 1 видео опубликовано, 3 поста запланировано.` |

## 8. Канал-архив (резервное хранилище)

- Отдельный приватный TG-канал `@robotec_factory_archive` (или любого клиента).
- Бот отправляет туда каждое готовое MP4 сразу после скачивания (см. спеку 04).
- Используется как «резервная память» (по запросу пользователя): если файл на
  SSD уже удалён (старше 7 дней), копия остаётся в TG.

## 9. n8n-воркфлоу (транспортные)

> Принцип: n8n не содержит бизнес-логики. Каждая нода — это "получил → переслал в
> Hermes → получил ответ → отправил в TG".

### 9.1 `wf-tg-incoming` (приём сообщений/команд/callbacks — единый вебхук)
```
[Telegram Trigger: message | callback_query | channel_post]
   ├─ [Code: базовая sanity-проверка (tg_user_id whitelist)]   ← первая нода
   ├─ [IF not allowed]: [Telegram: "Доступ запрещён"] + STOP
   ├─ [HTTP POST → Hermes :8000/tg/handle
   │     body = { from, chat_id, text?, callback_data?, message_id }]
   │     response = {
   │       method: "sendMessage" | "sendVideo" | "editMessageReplyMarkup",
   │       params: { chat_id, text, video_path?, reply_markup? }
   │     }
   └─ [Telegram: выполнить method из ответа Hermes]
```

> Вся логика команд (`/start`, `/mode`, `/onboard`, inline-кнопок, ожидание
> ответа при `edit`) — внутри Hermes-эндпоинта `/tg/handle`. n8n просто передаёт.

### 9.2 `wf-tg-send` (исходящие — алерты, уведомления о готовности)
Вызывается из других воркфлоу (creatify-webhook, publish-status) и из Hermes:
```
[Webhook from any wf, body={chat_id, text, video_path?, buttons?, parse_mode?}]
   └─ [Telegram: sendMessage / sendVideo с reply_markup]
```

> Это **единственный** способ отправить сообщение в TG из системы — единая
> горловина для логирования и рейт-лимита (Telegram ~30 сообщений/сек).

## 10. Безопасность

- `TELEGRAM_BOT_TOKEN` в n8n Credentials (зашифрован).
- Whitelist user_ids проверяется на **первой** ноде каждого воркфлоу.
- Callback-данные содержат id сущности → серверная проверка прав (оператор может
  approve только то, что в статусе pending).
- Файлы из `/var/media` отправляются как `InputFile`, не как публичная ссылка
  (внутренний путь не светится).

## 11. Критерии готовности

1. Бот отвечает на `/start`, `/status`, `/mode`.
2. Whitelist работает — посторонний id получает «Доступ запрещён».
3. Полный ручной цикл: 4 сообщения с кнопками, корректная обработка
   approve/edit/reject на каждом.
4. Все алерты (раздел 7) приходят при соответствующих событиях.
5. Готовые видео отправляются в канал-архив.
6. Авто-режим: бот шлёт инфо-сообщения без кнопок, без зависания на паузах.
