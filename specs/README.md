# Контент-завод — спецификации

Витринный демо-продукт для автоматизированной генерации и публикации короткого
вертикального видео-контента в соцсетях. Текущий демонстрационный кейс —
**robotec.ru** (B2B-интегратор промышленной робототехники KUKA).

## Первоисточники (API-документация)

| Блок | Сервис | Документация | Авторизация |
|------|--------|--------------|-------------|
| Аналитика | ScrapeCreators | https://docs.scrapecreators.com/ | заголовок `x-api-key` |
| Генерация | Creatify | https://docs.creatify.ai/ | заголовки `X-API-ID` + `X-API-KEY` |
| Автопостинг | Postmypost | https://help.postmypost.io/docs/api/ | `Authorization: Bearer <token>` |

## Архитектура в одной строке

`URL клиента → Онбординг(Hermes) → [Hermes (мозг, 4 субагента + cron + TG-бот) ↔ n8n (руки: HTTP/вебхуки) ↔ SQLite (бизнес-данные)] → TG (интерфейс)`

- **Онбординг** (спека 08) — по одному URL сайта клиента завод сам выводит нишу,
  тон, аудиторию, соцсети и конкурентов. **Ключевой демо-момент для продаж.**
- **Hermes** (deepseek v4 через opencode zen) — мозг И TG-интерфейс одновременно:
  оркестратор цикла, 4 субагента (через `delegate_task`), приём/отправка TG
  (нативный `hermes gateway`), встроенный cron (`hermes cronjob`), долгоживущая
  память (`~/.hermes/state.db` + MEMORY.md).
- **n8n** — «руки»: HTTP-вызовы к scrapecreators/creatify/postmypost, приём
  вебхуков creatify, тяжёлые операции (скачивание MP4, парсинг сайтов).
  Вызывается Hermes через `terminal` (`curl`) или MCP-мост. **TG в n8n — только
  Send-ноды для алертов** (приём в Hermes, чтобы не конфликтовать).
- **SQLite** `factory.db` — бизнес-данные (clients, topics, scripts, generations,
  posts, logs). Не дублирует agent-memory Hermes.
- **Дашборд** (P2, спека 09) — клиентский веб-интерфейс.

> Подробности и точные команды — в спеке **11-amendments** (правки к 03/06/10
> после spike T-030).

## Фазы и приоритеты (дедлайн MVP — завтра)

- **P0 — обязательный вертикальный срез (завтра):** сервер → n8n → Hermes →
  **онбординг из URL** → аналитика → генерация видео → ручной постинг → TG-бот.
  Полный цикл в ручном режиме, чтоб показать клиенту на переговорах.
- **P1 — автопилот (завтра, если успеваем):** автопостинг + авто-режим
  (утренний цикл без человека) + устойчивость (рётраи, алерты).
- **P2 — после закрытия клиента:** аналитика собственных роликов, веб-дашборд
  (Next.js), мульти-тенантность, EN.

> Правило приоритизации для разработчика: если не успеваешь — режь по P0.
> P0 должен быть полностью рабочим к показу. Онбординг (T-000) — часть P0,
> без него «магии» для клиента нет.

## Текущий демо-клиент: Robotec (robotec.ru)

- **Ниша:** B2B, промышленная робототехника, интегратор KUKA (Сколково).
- **Аудитория:** владельцы производств, директора заводов, главные инженеры, технологи.
- **Тон:** экспертно-деловой, ROI/окупаемость, без сленга.
- **Бренд-лица нет** → используем библиотечные AI-аватары creatify
  (инженерный/экспертный тип) + закадровый голос на русском.
- **Форматы для Reels/Shorts:** «залипательные» демо роботов, «было/стало»
  кейсы, разрушение мифов о роботизации, обзоры оборудования.
- **Хронометраж:** 15–30 сек (URL-to-video, биллинг по 30-сек порциям).
- **Площадки (MVP):** Instagram (Reels), YouTube (Shorts), TikTok, Telegram,
  VK. Threads/X — текстовые посты. Rutube — при возможности. **Max исключён**
  (не поддерживается postmypost).
