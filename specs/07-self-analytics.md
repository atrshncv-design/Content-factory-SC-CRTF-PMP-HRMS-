# Спека 07 — Аналитика собственных роликов

**Фаза:** P2 · **Статус:** к реализации после P0/P1

> Без этого блока завод «слепой»: публикует, но не знает, что зашло. Эта спека
> замыкает петлю обратной связи и кормит Аналитика дайджестом успехов.

## 1. Цель

1. Регулярно собирать метрики по **собственным** публикациям (просмотры, лайки,
   комментарии, репосты, охват) из соцсетей.
2. Хранить временные ряды (как метрики растут со временем).
3. Готовить **дайджест эффективности** для субагента-Аналитика, чтобы следующие
   темы выбирались с учётом того, «что работает у нас».

## 2. Источник данных

Используем тот же **ScrapeCreators** (уже интегрирован в P0) — он умеет тянуть
метрики по конкретным постам/видео. postmypost метрик охватов не отдаёт
(только статус публикации), поэтому берём напрямую из соцсетей.

| Платформа | Эндпоинт scrapecreators | Ключевые поля ответа |
|-----------|-------------------------|----------------------|
| Instagram | `GET /v1/instagram/post?url=<reel_url>` | `like_count`, `comment_count`, `view_count`, `reshare_count` |
| YouTube | `GET /v1/youtube/video?id=<id>` | `view_count`, `like_count`, `comment_count` |
| TikTok | `GET /v1/tiktok/video-info?url=<url>` | `play_count`, `digg_count`, `comment_count`, `share_count` |
| Twitter/X | `GET /v1/twitter/tweet?id=<id>` | `view_count`, `like_count`, `retweet_count`, `reply_count` |

> Для VK/Telegram/Rutube прямых метрик в scrapecreators меньше — там берём что
> доступно (подписчики канала, просмотры поста если отдаётся).

## 3. БД — новые таблицы (миграция 003)

### `post_metrics` — временные ряды метрик
```sql
CREATE TABLE post_metrics (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  post_id      INTEGER NOT NULL REFERENCES posts(id),
  platform     TEXT NOT NULL,
  ts           TEXT NOT NULL DEFAULT (datetime('now')),
  views        INTEGER,
  likes        INTEGER,
  comments     INTEGER,
  shares       INTEGER,
  reach        INTEGER,
  raw_json     TEXT,                       -- весь ответ для аудита
  UNIQUE(post_id, platform, ts)
);
CREATE INDEX idx_pm_post ON post_metrics(post_id);
CREATE INDEX idx_pm_ts ON post_metrics(ts);
```

### `external_urls` — связь постов с публичными ссылками (если ещё нет)
> Поле `external_url` должно быть в `posts` (см. T-103/checklist). Если нет —
> добавить в миграции 003.

## 4. Что измеряем и как считаем «успех»

### Метрики сырые (по платформам)
- **views** — просмотры (основная).
- **likes** — лайки.
- **comments** — комментарии (мера вовлечённости/дискуссии).
- **shares** — репосты (мера виральности).
- **reach** — охват (где отдаётся).

### Производный индекс вовлечённости (ER)
```
ER = (likes + comments*3 + shares*5) / max(views, 1)
```
> Комментарии и репосты весомее лайков — они требуют больше действий и сильнее
> коррелируют с «зацепило».

### Виральность (по сравнению с бенчмарком клиента)
Для каждой платформы считаем медианный ER за последние 30 дней по всем постам
клиента. Ролик считается «выстрелившим», если его ER > 1.5 × медиана.

## 5. Поток данных

### `wf-self-analytics` (cron 21:00 ежедневно)
```
[Cron: 0 21 * * *]
   │
   ├─ [SQLite: SELECT id, external_url, target_platforms FROM posts
   │          WHERE status='published' AND published_at >= now-14d]
   │
   ├─ [Split по постам] → для каждого:
   │     ├─ [HTTP scrapecreators: метрики по URL для каждой платформы]
   │     │     (retry 2x; при 4xx — skip + warn)
   │     └─ [SQLite: INSERT post_metrics (post_id, platform, ts, views, likes,...)]
   │
   ├─ [Code: посчитать ER по каждому посту, медиану по платформе за 30д,
   │        выделить "выстрелившие" (ER > 1.5×median)]
   │
   └─ [HTTP → Hermes :8000/internal/performance-digest]
        payload = {
          "top_posts": [...],              // топ-5 за 14 дней
          "flop_posts": [...],             // анти-топ (что не зашло)
          "best_formats": ["demo","мифы"], // по тегам сценариев
          "best_platforms": {"instagram": 0.04, "tiktok": 0.07},
          "median_er_by_platform": {...}
        }
```

> Cache hit у scrapecreators = 0 кредитов — повторный опрос того же поста
> недорог. Но метрики меняются, так что cache miss (1 кредит) на свежие посты
> — это норма. Бюджет: ~30 постов × 4 платформы × ~1 кредит = ~120 кредитов/мес
> на аналитику (вписываемся).

## 6. Использование Аналитиком

В промпт субагента-Аналитика (спека 03) подмешивается **краткий дайджест**:

```
Дайджест за последние 14 дней:
- Топ-3 ваших ролика:
   1. «Как сварочный робот снижает брак» — IG, 145k просмотров, ER 8.2%
   2. «4 мифа о роботизации» — TikTok, 89k, ER 6.1%
   3. ...
- Формат, который заходит лучше всего: «разрушение мифов» (медианный ER 5.8%)
- Платформа-лидер: TikTok (медиана 4.1%) > Instagram (2.9%)
- Что НЕ зашло: длинные обзоры оборудования (ER < 1%)

Учитывай это при выборе темы: предпочитай форматы из "best_formats".
```

Это делает Аналитика **обучающимся**: он видит, что у клиента «мифы» заходят
лучше «обзоров», и сдвигает выбор тем.

## 7. Дайджест в TG и дашборд

- **В TG:** раз в неделю (воскресенье 10:00) бот присылает оператору
  сводку: «На этой неделе: 3 видео, лучший — …, ER-медиана …».
- **В дашборде** (P2, спека 09): страница `/analytics` с графиками и таблицами.

## 8. Краевые случаи

| Случай | Поведение |
|--------|-----------|
| Пост опубликован < 24 ч назад | метрики могут быть низкими/нестабильными — собираем, но в дайджест не включаем (минимум 24 ч жизни) |
| `external_url` пустой | skip + warn (нечего опрашивать) |
| scrapecreators 4xx по URL (пост удалён/приватный) | mark `post_metrics.raw_json={error}`, не падать |
| Платформа не отдаёт reach | поле `reach=NULL`, считаем ER по views |
| Новый клиент, данных < 7 дней | дайджест пустой → Аналитик работает без обратной связи (нормально для старта) |

## 9. Что заложить уже в P0 (чтобы не переписывать в P2)

- В `posts` — поле `external_url` (публичная ссылка на опубликованный пост).
  Заполняется при `publication_status=1` из ответа postmypost (если отдаёт) или
  ищется вручную первым временем.
- В `scripts` — поле `format_tag` (демо/мифы/кейс/обзор) для будущей агрегации
  «какие форматы заходят». Заполняет Сценарист.

## 10. n8n-воркфлоу (дополнительно)

- `wf-self-analytics` — сбор метрик (раздел 5).
- `wf-weekly-digest` (cron `0 10 * * 0`) — еженедельная сводка в TG.

## 11. Критерии готовности

1. `post_metrics` наполняется раз в день для опубликованных постов.
2. Дайджест корректно считает ER и определяет «выстрелившие» ролики.
3. Промпт Аналитика получает дайджест (видно в логах промптов).
4. При < 7 дней данных — дайджест пустой, ошибки нет.
5. Еженедельная сводка приходит в TG.
6. Метрики отображаются в дашборде (P2.1).
