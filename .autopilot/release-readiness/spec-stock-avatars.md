# Спека фичи: «Стоковые аватары creatify в выборе аватара»

Решение пользователя (16.08, гриллинг, 3 вопроса):
1. **Когда показывать**: ВСЕГДА — свои (approved из `custom_avatars`) первыми, стоковые — ниже.
2. **Сколько стоковых**: фиксированная подборка **~15 разных** (мужчины и женщины, разные сцены/возраст/типы), НЕ все 514, без листания и пагинации. Кураторский список id из `/api/personas/` (стоковые, не byoa).
3. **Формат показа**: сначала **превью-фото** (сетка/альбом, `preview_image_9_16`), затем кнопки выбора с именами.

## Контекст (разведка 16.08)

- `GET /api/personas/` (бесплатный) возвращает 826 персон аккаунта: 514 стоковых creatify (тип realistic/styled, `creator_name`, `preview_image_9_16`, `preview_video_9_16`, `gender`, `style`, `video_scene`) + 312 своих BYOA (в `preview_image_16_9` есть `byoa`).
- Ветка AVV в wf-tg-bot (тикет 15, 37 нод): `AVV Start → AVV HTTP state → AVV Build avatars (SELECT id, persona_id, creator_name FROM custom_avatars WHERE status='approved') → AVV HTTP avatars (db-bridge) → AVV Ask avatar (кнопки avv_sel:<id>) → AVV Save avatar (quick_payload.avatar_id) → AVV Topic → AVV Dur apply → ... → AVV Build submit (creator: r.avatar_id)`.
- ⚠️ **БАГ (чинится в этой фиче)**: кнопка `avv_sel:<id>` несёт **локальный id** `custom_avatars.id`, а lipsync-валидатор требует **UUID** персоны → при выборе своего аватара `creator` уйдёт невалидным (число вместо UUID) и lipsync вернёт error. Нужно: кнопка несёт **persona_id** (UUID), стоковые — их id из `/api/personas/`.

## Требования (hard)

1. **Свои аватары** (approved из custom_avatars) — первыми, как сейчас (кнопки `avv_sel:<persona_id>`).
2. **Стоковые**: фиксированный список ~15 id (кураторский, оба пола, разные сцены) — после своих. Метка-разделитель «🎭 Стоковые аватары creatify» + 15 кнопок с именами.
3. **Превью**: перед кнопками — альбом/сетка фото стоковых (`preview_image_9_16`), до 10 фото на сообщение (лимит Telegram sendMediaGroup) → 2 сообщения-альбома по 8+7 (или 10+5) ИЛИ одно фото-коллаж. Решение: 2 sendMediaGroup (по 8 и 7), затем кнопки. Если Telegram-нода n8n не умеет media group — отправка отдельных sendPhoto (по одному, до 10) + текст. (Уточнить реализуемость при имплементации; минимально: 1-е сообщение — фото, 2-е — кнопки.)
4. **Фикс бага**: `AVV Ask avatar` для своих → кнопка `avv_sel:<persona_id>` (не id); `AVV Save avatar` сохраняет `avatar_id` = UUID; `AVV Build submit` → `creator: avatar_id` (UUID) — уже ок после фикса.
5. **Порядок**: свои (approved, по id DESC) → стоковые. Если своих нет — только стоковые, без сообщения «Сначала создай аватар» (стоковые доступны всегда).
6. **Кэш**: список стоковых — константа в jsCode (id + имя + preview_url), НЕ GET /api/personas/ при каждом запросе (0 кредитов, но 826 персон — тяжело; 15 id захардкожены).
7. **Никаких платных вызовов**: превью — прямые URL CDN (бесплатно), выбор стокового → lipsync POST платит как обычно (5 кред/30с) — это пользовательский платный прогон, не часть фичи.

## Вне скоупа

- Пагинация/поиск/фильтр по 514 стоковым.
- Динамическая подгрузка списка стоковых из API в бота.
- BYOA-персоны пользователя в общем списке (они уже в custom_avatars через upload_avatar).
- Модерация/управление аватарами.
