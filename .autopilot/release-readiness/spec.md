# Спецификация: доводка контент-завода к сдаче (release readiness)

## Задача

Пользователь 4 дня собирал контент-завод с разными моделями и получал версии с багами. Завтра (17.08.2026) проект нужно сдать. Сам пользователь видел вживую только часть бота и сообщает: «полные сценарии от аналитики до автопостинга не работают, видео не всегда приходят в чат, сценарии неправильно форматируются и отправляются на генерацию кривыми, кнопки не все работают правильно». Нужно найти все дыры, закрыть их и отдать проект, в котором пользователь уверен, не тратя при этом ни кредита scrapecreators/creatify — платную приёмку он проведёт сам.

## Решение

Полный бесплатный аудит всего scope (24 воркфлоу + бот + hermes-скиллы + инфра + документация) против live-состояния сервера, фиксы найденного волнами, деплой с согласия пользователя, финальный отчёт «что готово / что осталось на платные тесты». Критерий сдачи: каждый сценарий из приёмочного чек-листа либо доказанно работает бесплатными методами, либо доказанно корректен «до точки списания» и помечен для платного теста пользователя.

## Решения по реализации

- **Метод «0 кредитов»** (R05): статический анализ JSON воркфлоу, симуляции с мок-ответами (существующий sim-подход проекта), чтение executions/активации через n8n sqlite, TG-сообщения (бесплатны). Платные API не вызываются вообще; даже балансы — только если подтверждённо бесплатны.
- **Демо-клиент — Robotec** (G04): сдаём на существующем профиле (БД `clients.id=1`, `settings.active_client_id=1`), пересоздание не нужно.
- **Источники правды**: live n8n (sqlite в контейнере) для «что реально работает»; репо `workflows/*.json` (синк 16.08) для правок; `.scratch/` — только история, с известными ловушками: `review-full-14aug/fixes/wf-publish.json` содержит баговый switch, `client-profiles/base/*` — компактный устаревший формат.
- **Схема БД**: эталон = `infra/db/001_init.sql` + `002_sessions.sql` + `migrate-client-profiles.py` + `migrate-client-profiles-v2.py` + v3 (на сервере, файла нет → таск: восстановить миграцию v3 в репо).
- **Деплой**: через существующий конвейер apply_fix.sh-подхода; каждый деплой — отдельное «ок» пользователя (внешнее действие).
- **Формат находки** (контракт аудиторов): `{id, кластер, severity 🔴/🟠/🟡, файл:нода, доказательство, гипотеза фикса, платный_риск: да/нет}`.
- **Правила проекта (AGENTS.md) обязательны для фиксов**: TG v1.2 / switch v3.4, neverError вложенный, esc(), callback_data `={{ }}`, keypair-заголовки для платных HTTP, секреты — только имена переменных.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| аудит-кластер (×10) | свои воркфлоу/файлы | отчёт находок в формате выше | метод поиска |
| фикс-таск (×N) | один файл/одна цепочка | готовый JSON/файл + отчёт валидации (0 issues, sim) | промежуточные правки |
| оркестратор | манифест, state.js, гейты, деплой-гейт | отчёты пользователю | контексты субагентов |

Швы для проверки: (1) формат находки аудитора; (2) валидация фикса — существующий валидатор проекта (index/type, replyMarkup, BFS) + sim-прогон. Phase 5 тестирует только через них.
