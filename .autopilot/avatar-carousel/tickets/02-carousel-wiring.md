# 02 — Карусель аватаров в wf-tg-bot.json

**Требования:** R02, R04, R05, R06, R07, A01 (частично R01.1, R01.3)
**Blocked by:** 01, 03
**Зона:** `workflows/wf-tg-bot.json` + `tests/`
**Волна:** 2
**Status:** ready

## Что должно заработать

Пользователь жмёт «🎭 Видео с аватаром» — приходит ОДНО сообщение-карусель:
фото аватара, подпись-карточка (имя, возраст, ниша, позиция N/20) и кнопки
«✅ Выбрать | ➡️ Далее / 👤 Мои аватары | 📋 Меню | 🧹 Отмена». «Далее»
редактирует то же самое сообщение (фото+подпись+кнопки), чередуя М→Ж→М…;
круг из 20 замыкается. «Выбрать» ведёт в существующий сценарий (тема видео).
Чат не засоряется: message_id не меняется.

## Из брифа, дословно

> «Будем использовать механику карусели: человек видит 1 фото, текст и кнопки:
> Типа выбрать, далее, меню, отменить»
> «При нажатии кнопки далее (можно с эмодзи сделать) текущее сообщение
> заменяется на новое - появляется эффект карусели»
> «Можно карусель такую реализовать в рамках 1 сообщения: например, первое фото -
> мужское, далее ==> женщина ==> далее снова мужчина => и так пока не замкнётся
> круг из 20 аватаров»

## Что сделать (сводка; детали — в спеке)

1. **Бэкап** `workflows/` → `backups/<timestamp>/` до правок.
2. Впаять константу 20 из `.autopilot/avatar-carousel/avatars-20.json`
   (утверждённую пользователем) в Code-ноду карусели.
3. Вход: `AVV Start` → сборка payload (index 0) → `TG avv carousel` (sendPhoto,
   v1.2, n8n-клавиатура). Подпись: «🎭 N/20 · Имя, ~возраст · Ниша: …».
4. `avv_next:<index>` → Code (index+1 mod 20, payload нового слайда,
   kbApi в формате Telegram API) → HTTP-нода `editMessageMedia`
   (`api.telegram.org/bot{{$env.TELEGRAM_BOT_TOKEN}}/editMessageMedia`,
   neverError). Ошибка «message not found» → fallback sendPhoto нового слайда.
   Проверить доступность `$env.TELEGRAM_BOT_TOKEN` в контейнере n8n на сервере
   (`ssh factory 'docker exec <n8n-контейнер> printenv TELEGRAM_BOT_TOKEN'` —
   имя контейнера в DEPLOYMENT.md); если нет — не выдумывать, вернуть BLOCKED
   с командой для добавления в env.
5. answerCallbackQuery на клики карусели (паттерн существующих `* answer` нод).
6. «✅ Выбрать» → существующий callback `avv_sel:<persona_id>` → AVV Save avatar
   (путь уже есть; убедиться, что стоковые UUID работают — фиксы 16.08).
7. «👤 Мои аватары» → довести существующую ветку (AVV HTTP my avatars / AVV My
   avatars / TG avv my avatars) до рабочего списка своих с кнопками.
8. Выпилить недострой прошлой сессии: delete+send-ноды (TG avv delete next/
   select/my), AVV Select, TG avv selected, старый preview-флоу (AVV Build
   preview, AVV Preview sel, Switch avv preview, TG avv preview photo/text,
   TG avv ask avatar, TG avv none). Роутер сохраняет avv_sel (старые кнопки в
   чатах пользователей не должны умереть).
9. Тесты (шов pytest): константа 20/чередование/[0]=М; обе формы клавиатур;
   маршрутизация avv_next/avv_sel/avv_my_avatars в Switch cb; editMessageMedia
   payload (media/reply_markup/neverError); кнопки Меню/Отмена у карусели —
   в тесте покрытия (расширить исключения, если нужно).

## Критерии приёмки

- [ ] Вход «Видео с аватаром» = одно сообщение-карусель с полной клавиатурой (7 кнопок: Выбрать, Далее, Мои аватары, Меню, Отмена)
- [ ] «Далее» = editMessageMedia (то же message_id), круг 20 замыкается, чередование М/Ж, первый — М
- [ ] Подпись содержит имя/возраст/нишу/позицию N/20
- [ ] «Выбрать» → AWAIT_TOPIC, avatar_id в сессии; «Мои аватары» → список своих
- [ ] Старый флоу имён/превью удалён; avv_sel жив; недострой выпилен
- [ ] `python3 -m pytest tests/ -q` зелёный (включая новые тесты карусели)
- [ ] JSON воркфлоу валиден (без дублей имён нод), бэкап сделан
