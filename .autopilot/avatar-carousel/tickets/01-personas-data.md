## Что должно заработать

Собран и зафиксирован финальный список 20 стоковых аватаров creatify — 10 мужчин
и 10 женщин разного возраста и типажа — с карточкой каждого (имя, пол, возраст,
ниша, URL фото). Список готов к сверке с пользователем и к впаиванию в воркфлоу
тикетом 02. Никаких правок воркфлоу и БД.

## Из брифа, дословно

> «Выбери 20 разных аватаров из стоковых: по 10 мужчин и женщин разного возраста
> и типажа - будем только их использовать.»
> «в сообщении к фото краткая инфа об аватаре: кто? сколько лет? для какой ниши
> лучше использовать? и тд»

## Разделы спецификации

Истории 4, 5; Решения §6 (правила разнообразия/ниши/возраста); interfaces.md
(контракт `avatars-20.json`).

## Как

1. Выгрузить персон с сервера (бесплатный GET, 0 кредитов):
   `ssh factory` → прочитать `~/factory/.env` (имена: `CREATIFY_API_ID`,
   `CREATIFY_API_KEY`) → curl `https://api.creatify.ai/api/personas/` с
   keypair-заголовками (точный формат заголовков — DEPLOYMENT.md, раздел
   «Проверенные структуры ответов API»). Пагинация: выгрузить ВСЕ стоковые
   (тип realistic/styled, НЕ byoa; ~514 шт). Дамп сохранить в
   `.autopilot/avatar-carousel/personas-raw.json` (в репо; это метаданные
   персон, не секреты — если в дампе окажутся ключи/токены, вычистить).
2. Кураторский отбор 20 по правилам спеки: на каждый пол ≥4 возрастных
   диапазона (≈20-е…≈50+), ≥3 типажа по сцене/стилю, без дублей персон.
   Приоритетные кандидаты — 15 уже отобранных (id в jsCode ноды
   `AVV Carousel next` в `workflows/wf-tg-bot.json`): сохранить подходящих,
   добавить недостающих до 10+10.
3. Возраст: из атрибутов API, если поля нет — оценка по фото CDN (инструмент
   анализа изображений, URL из `preview_image_9_16`) с пометкой «≈».
   Ниша: одна строка по сцене/стилю/возрасту (бизнес-эксперт, лайфстайл,
   товарка/ритейл, обучение…). Фото: `preview_image_9_16`.
4. Порядок в списке: чередование М/Ж, элемент 0 — мужчина (п.4 брифа).

## Критерии приёмки

- [ ] `personas-raw.json` — полный дамп стоковых персон (без секретов)
- [ ] `avatars-20.md` — человекочитаемый список 20 (имя/пол/возраст/ниша/фото-URL) для сверки с пользователем
- [ ] `avatars-20.json` — контракт из interfaces.md: 20 объектов, поля id/name/gender/age_label/niche/img, порядок чередуется m/f, [0] — m; 10/10; все id — валидные UUID из дампа; URL фото открываются (HEAD-проверка или наличие в дампе)
- [ ] Правила разнообразия соблюдены и видны в списке (возрастные группы и типажи различимы)
- [ ] 0 кредитов списано (только GET), 0 правок workflows/ и БД
