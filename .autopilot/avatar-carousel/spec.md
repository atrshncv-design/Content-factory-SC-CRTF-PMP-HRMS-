# Спецификация: карусель стоковых аватаров + аудит TG-кнопок

## Задача

Пользователь бота выбирает аватара для видео и не видит кнопок — сообщение «🎭 Выбери аватара…» повисает без действий, сценарий встаёт. Плюс нет уверенности, что в остальных сообщениях кнопки вообще есть и работают. Выбор из 514 стоковых аватаров creatify сделан «кнопками с именами», что неудобно: не видно, кто это, сколько лет, под какую нишу.

## Решение

Выбор аватара становится каруселью в одном сообщении: фото, карточка «кто / возраст / ниша» и кнопки ✅ Выбрать · ➡️ Далее · 👤 Мои аватары · 📋 Меню · 🧹 Отмена. «Далее» листает фото на месте (сообщение редактируется, не дублируется), чередуя мужчин и женщин; круг из 20 подобранных аватаров замыкается. Параллельно — полный аудит: во всех сценариях wf-tg-bot у каждого исходящего сообщения есть рабочие кнопки навигации, закреплённые автотестом.

**Исключения из правила «Меню+Отмена у каждого исходящего»** (полный список, wf-tg-bot):
`TG start`, `TG cancel`, `TG ping`, `TG status`, `TG unknown` — только 📋 Меню (Отмена не нужна: нет активного шага); `TG sh video` — sendVideo без клавиатуры, кнопки идут сразу следующим сообщением `TG sh buttons`; все `* answer`-ноды — это answerCallbackQuery, не исходящие сообщения.

## Решения по реализации

1. **editMessageMedia через HTTP-ноду.** Нода Telegram (v1.2) не умеет редактировать медиа (подтверждено документацией n8n) — только текст/caption/клавиатуру. Листание: HTTP POST `api.telegram.org/bot{{$env.TELEGRAM_BOT_TOKEN}}/editMessageMedia`, тело: chat_id, message_id (сообщение с нажатой кнопкой — уже есть в Parser), media {type:photo, media:URL, caption}, reply_markup в формате Telegram API (`inline_keyboard: [[{text, callback_data}]]` — НЕ n8n-формат rows). Почему: единственный способ заменить фото в том же сообщении; паттерн секретов `$env.VAR` в HTTP-нодах устоявшийся в репо.
2. **Первое сообщение — нодой Telegram** (sendPhoto, v1.2) с n8n-клавиатурой; все последующие — editMessageMedia.
3. **Карусель stateless**: индекс живёт в callback_data (`avv_next:<index>` → показывает index+1 по модулю 20). Не зависит от сессии, переживает перезапуск, два быстрых клика не ломают порядок.
4. **Один callback выбора**: `avv_sel:<persona_id>` — существующий обработчик AVV Save avatar. Карусель не плодит новый вид callback; недостроенные прошлой сессией avv_select/удалить+послать-ноды выпиливаются.
5. **Список 20 — константа в jsCode** (id, имя, пол, возраст, ниша, URL фото CDN). 0 вызовов API в рантайме. Порядок чередуется М/Ж, первым — мужчина.
6. **Данные для отбора**: бесплатный GET /api/personas/ с сервера (решение брифинга) — реальные пол/стиль/сцена/возраст если есть. **Правило разнообразия** («разного возраста и типажа»): на каждый пол — не менее 4 возрастных диапазонов (≈20-е, ≈30-е, ≈40-е, ≈50+) и не менее 3 разных типажей по сцене/стилю (например: студийный/бизнес, лайфстайл/кэжуал, ритейл/товарка), без дублей персон. **Правило ниши**: ниша = одна строка, назначается по сцене/стилю/возрасту из API (бизнес-эксперт, лайфстайл, товарка/ритейл, обучение и т.п.); итоговый текст — в списке 20. **Правило возраста**: возраст из API, если поля нет — визуальная оценка по фото CDN с пометкой «≈». Итоговый список (имя/пол/возраст/ниша/фото) — на быструю сверку пользователю до впаивания. 0 кредитов.
7. **answerCallbackQuery** на клики карусели — паттерн существующих `* answer` нод.
8. **Вход сценария**: AVV Start → сразу карусель (первый М-аватар). Старый флоу «имена → превью» (AVV Build preview, AVV Preview sel, Switch avv preview, TG avv preview photo/text, TG avv ask avatar, TG avv none) удаляется — его заменяет карусель. «Мои аватары» (свои BYOA) остаются списком по кнопке — без карусели.
9. **Тексты**: экранирование Markdown (`esc()`), статика без `_`, callback_data только `={{ expr }}` — правила AGENTS.md.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `AVV_STOCKS` константа | список 20 (id/имя/пол/возраст/ниша/фото) | массив в jsCode Code-нод | источник (API-вытяжка), порядок чередования |
| `AVV Carousel build` (Code) | сборка payload карусели | `{photo, caption, index, kbN8n, kbApi}` по входному index | форматирование подписи, экранирование |
| `AVV Carousel edit` (HTTP) | editMessageMedia | — | neverError, тело Telegram API |
| `TG avv carousel` (Telegram) | первое сообщение карусели | sendPhoto + inlineKeyboard | — |
| Роутер `Switch cb` | маршрутизация callback | выходы avv_next, avv_sel, avv_my_avatars | — |
| Тест-шов (единственный) | `pytest tests/` (test_wf_tg_bot.py + тест алертов) | структурные проверки wf JSON + исполнение jsCode | — |

Поведение проверяется только через шов pytest: покрытие кнопками (wf-tg-bot и wf-tg-alerts), маршрутизация callback, формы клавиатур (n8n и Telegram API), постоянство константы (20/чередование/разнообразие), пути роутера.
